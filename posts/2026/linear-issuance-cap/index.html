Linear Issuance Tapering for Ethereum

A minimal modification to Ethereum’s issuance curve that preserves current incentives while tapering new issuance to zero at a 50% staking ratio.
Published

May 10, 2026

[Intro paragraph — reference to staking ratio post; motivation for proposing a specific curve.]

tl;dr

  • Above a 50% staking ratio, incentivising further stake actively harms Ethereum’s security; the proposed curve tapers issuance to zero there.
  • At the current staking ratio (~1/3), yield and issuance are unchanged — making this the most conservative possible intervention.
  • The anti-discouragement-attack property of the existing curve is preserved for staking ratios below 1/6.
  • The modification has a single free parameter \(k\), which is fully determined by the current staking ratio.

Analytic Form

Let \(f\) denote the staking ratio (ETH staked / total ETH supply) and let \(r(f)\) and \(I(f)\) be the consensus-layer nominal yield and total annual issuance under the current curve:

\[r(f) = \frac{B \cdot E}{\sqrt{f \cdot S \cdot 10^9}}, \qquad I(f) = r(f) \cdot f \cdot S = B \cdot E \sqrt{\frac{f \cdot S}{10^9}}\]

where \(B = 64\) (BASE_REWARD_FACTOR), \(E \approx 82{,}181\) (epochs per year), and \(S \approx 120.5 \times 10^6\) ETH (total supply).

The proposed modification multiplies both curves by a piecewise-linear coefficient \(c(f)\):

\[c(f) = \begin{cases} k\,(1 - 2f) & f \leq \tfrac{1}{2} \\ 0 & f > \tfrac{1}{2} \end{cases}\]

giving modified yield and issuance:

\[r_\text{new}(f) = c(f)\,r(f), \qquad I_\text{new}(f) = c(f)\,I(f)\]

Calibration

The constant \(k\) is determined by requiring that yield (and hence issuance) is unchanged at the current staking ratio \(f_0\):

\[c(f_0) = 1 \;\Longrightarrow\; k = \frac{1}{1 - 2f_0}\]

With \(f_0 = \tfrac{1}{3}\) (the current staking ratio), this gives \(\boldsymbol{k = 3}\).

Anti-Discouragement Attacks

A key security property of the current curve is that total issuance \(I(f) \propto \sqrt{f}\) is strictly increasing in \(f\): an adversary who forces validators to exit does not gain a relative advantage, because the total reward pool shrinks. Under the proposed curve:

\[I_\text{new}(f) \propto (1 - 2f)\sqrt{f}\]

Differentiating:

\[\frac{dI_\text{new}}{df} \propto 1 - 6f\]

This is positive for \(f < \tfrac{1}{6} \approx 16.7\%\), so the anti-discouragement property is preserved at the staking ratios where it is most relevant. Above \(f^* = \tfrac{1}{6}\), total issuance decreases as the staking ratio grows — creating an additional natural disincentive against excessive staking in the high-\(f\) regime.

Consensus Layer Spec

The analytic form translates to a minimal change in the Ethereum consensus layer spec: only get_base_reward_per_increment is modified.

New Constants

Two parameters govern the new curve.

Constant Value Notes
SATURATION_BALANCE Gwei(60_250_000 * 10**9) Total active balance (in Gwei) at which issuance falls to zero; set at the hard fork to approximately half the current ETH supply
BASE_REWARD_FACTOR uint64(192) Replaces the current value of 64; incorporates the calibration factor \(k = 3\)

SATURATION_BALANCE plays the role of \(f_\mathrm{cap} \cdot S\) from the analytic form — it is the absolute staking level corresponding to the 50% threshold, expressed in Gwei rather than as a fraction of the supply. BASE_REWARD_FACTOR remains the overall issuance scaling parameter, its value adjusted to preserve current reward levels.

Modified Function

The current function:

def get_base_reward_per_increment(state: BeaconState) -> Gwei:
    return Gwei(
        EFFECTIVE_BALANCE_INCREMENT * BASE_REWARD_FACTOR
        // integer_squareroot(get_total_active_balance(state))
    )

is replaced by:

def get_base_reward_per_increment(state: BeaconState) -> Gwei:
    total_active_balance = get_total_active_balance(state)
    if total_active_balance >= SATURATION_BALANCE:
        return Gwei(0)
    return Gwei(
        EFFECTIVE_BALANCE_INCREMENT * BASE_REWARD_FACTOR
        * (SATURATION_BALANCE - total_active_balance)
        // (SATURATION_BALANCE * integer_squareroot(total_active_balance))
    )

The factor (SATURATION_BALANCE - total_active_balance) / SATURATION_BALANCE is the discrete equivalent of \(c(f)/k = 1 - 2f\). Structuring the division as a single // at the end avoids the double floor-division of the original and preserves precision.

Calibration

The two changes together reproduce the existing per-increment reward at any given staking ratio \(f_0\). Letting \(D = f_0 \cdot S\) (total active balance at the calibration point), the new reward per increment is:

\[\frac{\texttt{EBI} \times 192 \times (\texttt{SATURATION\_BALANCE} - D)}{\texttt{SATURATION\_BALANCE} \times \sqrt{D}}\]

At \(f_0 = \tfrac{1}{3}\), with \(\texttt{SATURATION\_BALANCE} = \tfrac{S}{2}\):

\[\frac{\texttt{SATURATION\_BALANCE} - D}{\texttt{SATURATION\_BALANCE}} = \frac{\tfrac{S}{2} - \tfrac{S}{3}}{\tfrac{S}{2}} = \frac{\tfrac{1}{6}}{\tfrac{1}{2}} = \frac{1}{3}\]

so the numerator factor becomes \(192 \times \tfrac{1}{3} = 64\), recovering the original BASE_REWARD_FACTOR exactly. More generally, the required value of BASE_REWARD_FACTOR for a calibration point \(f_0\) and threshold \(f_\mathrm{cap}\) is:

\[\texttt{BASE\_REWARD\_FACTOR} = \frac{64}{1 - f_0 / f_\mathrm{cap}} = \frac{64\,f_\mathrm{cap}}{f_\mathrm{cap} - f_0}\]

With \(f_0 = \tfrac{1}{3}\) and \(f_\mathrm{cap} = \tfrac{1}{2}\) this gives \(192\), consistent with \(k = 3\) from the analytic calibration.
